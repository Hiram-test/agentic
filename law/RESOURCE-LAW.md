# 资源法（基因）

来源：用户指定《从能力重叠到真正的资源整合》。按系统权力分工，不按能力分工。

## 权力
- 你：目标函数、不可逆操作、最终接受
- 科研总控：控制面与调度；不得自行提出-实现-运行-宣布成功
- GitHub：状态账本与证据账本；关键状态必须在此，不在聊天或虚拟机
- Cursor：高不确定性、与人耦合的工程台
- Build：边界明确的任务合同工厂
- Bot 虚拟机：有状态探索实验室（发现）。一次跑通不是正式证据
- GitHub Actions：无状态工厂与独立裁判（证明）

## 重叠只许三种用法
1. 替代：状态在 GitHub，换执行者能接着干
2. 竞争：只放在高熵决策，不重复写低价值代码
3. 独立验证：发现在 VM，证明在 Actions；制作者不能自证

## 调度
任务写成 Tcode / Tcompute。按不确定性、状态依赖、可复现、交互、权限、规模路由。
Build 连续两次过不了硬物理测试 → 升级给 Cursor。
Cursor 已调通的固定流程 → 降级成 Actions。

## 五条硬标准
1. 可无损交接
2. 同一计算作业 VM 与 Actions 都能跑
3. 制作者不能独立宣布成功
4. 昂贵智能只用于高熵决策
5. 每次运行都改变下一步资源分配
